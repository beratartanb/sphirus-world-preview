## 2. Recovery database: root cause (three stacked causes, all fixed at the source)

Ground truth comes from a new per-frame ABP log of the Motion Matching node's *final* database and animation
(`SHMABP|...|mmdb|mmanim`, logged from `Update_MotionMatching_PostSelection`, after every branch of `Update_MotionMatching`).

1. **The routed `SetDatabaseToSearch` calls had an empty `Database` pin.** The V1.3 installer wrote the database as a
   *pin default* through the graph helper (`set_pin_value(str(asset))`), which the object pin silently rejected; the graph
   dump shows the original AAMS calls with `Database<-GetVariable` and the SHME calls with no Database at all. On routed
   frames the node was told to search `None` (the `None` in the V1.3 telemetry) and kept its previous database. Fix: the
   databases live in typed member variables (`SHM_RecoveryDB`, `SHM_RunPivotDB`, `SHM_SprintPivotDB`) and the calls read
   them the way the original flow does. The routed frames now report `mmdb=PSD_SHM_Recovery*` (forced run `v131g2_s10`:
   56 routed frames on the recovery database, 0 on `None`).
2. **The recovery family fired while the idle layer owned the pose.** 238 of 298 forced-recovery frames were standing
   frames: the idle takeover (`BlendListByBool_5`) was active, the Motion Matching branch was not relevant and never
   searched (its logged database was the stale `PSD_CP2_JogStop` from the previous stop). A recovery from standing needs
   the MM branch back: `SHM_IdleWait` (already ANDed into the takeover condition) is now also true while the routed
   family is recovery / start transfer, so the takeover releases for exactly the routed frames.
3. **The V1.3 database still contained 46 walk-stop / turn entries** (it was a duplicate of `PSD_Dense_Stand_Walk_Stops`;
   the PoseSearch factory needs its schema dialog and the entry list is not scriptable), so the frames that *did* search
   it selected `SHM_M_Neutral_Walk_Stop_FL/FR_Lfoot`, not `SHM_Rec*`. The supported path that works headless: the generic
   `DataAssetFactory` with `data_asset_class = PoseSearchDatabase` creates an empty database with no dialog; schema and
   normalization set are exposed properties; entries come from the clips' BranchIn notifies (section 3).

4. **Search throttle.** AAMS binds the node's `SearchThrottleTime` to 1 s while a stop clip is held and 3 s in the
   settled idle; a database routed from standing was not searched inside the family's 0.35-0.6 s window. Now
   `SearchThrottleTime = SHM_IdleWait ? 0 : original` (`install_mm_throttle.py`).
5. **Continuing pose.** The routed calls used `InterruptOnDatabaseChange`; the held stop pose (continuing pose, negative
   cost bias) kept winning. The routes now use `InterruptOnDatabaseChangeAndInvalidateContinuingPose`, the mode AAMS
   itself uses for database switches.
6. **The Motion Matching node did not own the pose.** The decisive one: AAMS's transition system latches
   `CP_StopOwned` / `CP_StartOwned` (`CP_UpdateTransitionClock`) and plays stops and starts through its own sequence
   evaluators (`SequenceEvaluator_1` / `_0`, `BlendListByBool_17/_4/_3`), so from a stop until the next start the MM node
   is not relevant: its logged database is stale and any routed search is irrelevant to the pose. A routed family now
   releases both latches in `SHM_Snapshot` (`CP_StopOwned = CP_StopOwned AND NOT routed`, same for start); the MM node
   becomes the pose owner for the family window and the SHME stance snapshot idle holds the new stance afterwards.

Proof (forced run `v131g7_s10`, 30 FPS, `RouteForceRecovery` + `RouteRecoveryToDatabase`): 298 recovery-family frames ->
**280 on `PSD_SHM_Recovery_v131` playing `SHM_Rec_F_Lfoot` (192) / `SHM_Rec_F_Rfoot` (32) / `SHM_Rec_FL_Lfoot` (28) /
`SHM_Rec_FR_Rfoot` (28)**, 14 on the previous stop clip (the first frames of each episode, blend-in), 4 on walk stops
(cooldown edge); plant foot = SHME step foot on 82 % of the frames. 55 start-transfer frames -> 44 on

9 on the AAMS walk start (first frames), 2 loops. `CP_StopOwned/StartOwned` false on every routed frame. 0 Accessed-None,

Placement itself was correct: on a routed frame the entry branch searches the family database and the original flow does

one thing (`v131g2` ... `v131g7`).

## 6. Turn physics (velocity redirection)

Implemented in `SHM_UpdateRouting`: dV = v_desired - v (xy); `DeltaVMag`; `RedirectionAngle` (deg between v and
v_desired, only while moving with intent); `BrakeRequirement` = -dV . v_hat; **`RedirectionDemand` = |dV| / (mu g
t_step)** with `TractionMu` 0.7, `RedirectStepTime` 0.4 s (~275 cm/s per support step); `TurnClass` 0 normal /
1 committed (> `RedirectCommitted` 0.35) / 2 hard (> `RedirectHard` 0.8) / 3 reversal (angle > `RedirectReversalAngle`
135 and demand > committed). The hard-turn family now fires on demand (or, secondarily, on yaw momentum). A fast 45 deg at
sprint (|dV| ~ 375 cm/s -> demand 1.4) classifies harder than a slow 90 deg at walk (|dV| ~ 187 -> 0.7).
Results (V1.3.1 matrix runs, 30 FPS; the harness has no walk/jog 45/90/180 stages - the camera turns of suite 1 run at
sprint speed and suite 5 holds the strafe 90/180; walk and jog turns are NOT covered and are listed as such):

The camera turns redirect the velocity by 11-46 deg while the camera yaws 45-180 (the character keeps running along
the new camera forward); the model classifies by the actual velocity redirection, not the camera angle. The
classification is the consumed signal for telemetry / PMI; **the hard-turn route to the pivot databases is gated OFF**
(`RouteHardTurnToDatabase`, default false) after the matrix showed that overriding AAMS's own pivot choice with the
family-2 route costs 3-6 cm on every approach and up to 84 cm at a wall (the V1.3 version of that route was inert
because of the empty database pin, section 2). A straight acceleration also has a large dV, so the hard-turn candidate
now requires the redirection angle above `RouteHardTurnAngle` (60 deg) as well.
Turn classes named in the spec: NORMAL / COMMITTED / HARD / REVERSAL are `TurnClass` 0-3; BRAKE_REPLANT (braking impulse
without a heading change) and RECOVERY_AFTER_TURN (recovery family inside the cooldown after a turn) are derivable from
`Jb` / `fam` in the telemetry but are not separate runtime states.
