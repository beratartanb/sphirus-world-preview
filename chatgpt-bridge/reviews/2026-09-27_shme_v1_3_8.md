Date 2026-09-27. Project SPHIRUS (UE 5.8.1), production map `L_GR_SphirusHouse` unchanged (sha256 `bb9cf344160013cd...`,

**Result: PARTIAL V1.3.8.** The two player-reported failures are closed at their real owners with real-input evidence:
(1) the sprint animation freeze (a PoseSearch looping defect in the SHME redirect databases), (2) the standing mouse-turn
AAMS posture switch (a Blueprint montage turn system playing vendor AAMS clips over the SHM route). 135 / 180 deg standing

## 0. Why V1.3.7 said PASS while the player saw the defects

1. **Wrong input path.** The harness turned the camera with `PlayerController.AddYawInput`. Real mouse look is
   `IA_Look` -> `BP_GR_InputBase` (the controller) -> `TW_BeforeNativeLook` -> pawn `TW_CameraLookPulse` (camera-intent
   rebase, `TW_LastLookTime`) -> sensitivity (0.2 x legacy 2.5) -> `AddYawInput`. None of the pawn side ran in V1.3.7 tests.
   V1.3.8 harness option `"look":"ia"` injects open-loop mouse deltas through `IA_Look` (0.5 deg per unit, scripted vs
   observed yaw equal to 0.1 deg over 180 s); sprint is the held `IA_Ranger_GaitShift`; W is `IA_Move`.
2. **Freeze detector blind spot.** The V1.3.7 detector ignored low-speed windows, so a clamped clip next to a contact stop
   was never flagged. New `gait_freeze_report.py` classes: base stall (MM time not advancing), legs static (rendered feet),
   hard stop, montage takeover, MM ping-pong.
3. **Telemetry showed the Motion Matching pick, not the visible pose.** Standing turns were verified by the MM selection
   (`SHM_M_Neutral_Stand_Turn_*`), but a full-body DefaultSlot montage owned the screen. The harness now logs the montage's
   animation asset (`mona`). Stance was also sampled only at the END of each hold, after the turn had finished.

## 1. Real-map sprint freeze (priority 1)

**REPRODUCTION** (production map, real inputs, 60 fps cap reached 26-47 fps, 4 starts: exterior / house-west / path /
forest, 180 s each, mouse L/R sweeps 15-45 deg with drift, `v138a_frz_*`): run 2 froze **14.5 s** (12.0-26.7 s),
run 4 **6.4 s**. Context at onset (run 2, 11.93 s): db `PSD_LB_SprintLoops`, clip `A_LB_Sprint_Fwd`, time pinned at
**2.2667 s = clip length**, speed 490 cm/s, montage none, redirect inactive, latched hold db `PSD_SHM_Redirect_SprintLateral`,
FootLockTurn 1.0; rendered feet fore-aft range < 10 cm while the capsule moved 7 m (legs frozen).

**ROOT CAUSE** (UE 5.8 `PoseSearchDatabase.cpp`, verified in the engine source and in the assets). A database entry that is
synchronized from a `PoseSearchBranchIn` notify takes the notify range as its sampling range, and a sequence entry is
treated as LOOPING only when that range covers the whole clip (SamplingRange (0,0)). The SHME redirect databases were
authored with BranchIn `0 .. length-0.001`, so every loop inside them was indexed NON-looping (T3D export:
`A_LB_Sprint_Fwd, SamplingRange=(Max=2.265667)`). When a redirect episode selected the sprint loop from
`PSD_SHM_Redirect_SprintLateral`, the node created a non-looping player; after the episode the loop database kept choosing
the same clip as the continuing pose, so the player was never replaced, reached the end and clamped. Run 4 shows the chain
exactly: redirect pick of `A_LB_Sprint_Fwd` at 47.77 s -> continuing in `PSD_LB_SprintLoops` -> clamped from ~50 s.
The same defect pinned jog loops in older evidence (`A_CT_Jog_Fwd` 3.1 s in `v137v_rev_jog`, `A_CT_Jog_Left`,
`A_RB_Jog_RearLeft/Right`). A loop-seam search exclusion was tried first; it did not remove the trap (a stale index was also
served because the PoseSearch DDC key ignores notify edits; `v138c_frz_sprint_4` still froze 133 s) and was fully reverted.

**ACTUAL CHANGE** (`install_loop_branchin.py`, audit `v138_branchin_audit.py`): on LOOPING clips every BranchIn that fed a
database is re-authored over the full clip (47 entries); the 12 databases re-synchronized on save (loops now carry the
default looping range, pivots / starts / stops keep their ranges). Audit after: 109 loop entries full, 3 left untouched
(QA / unused: `PSD_GR_Sprint_ForwardLoop_QA`, `PSD_VMA_WalkForward`, `PSD_Ranger_Jog_F_Gate_CWF`).

**AFTER** (`v138d_*`, same starts and inputs): 4 x 180 s sprint + 180 s jog: **0 base-stall s, 0 legs-static s** (was
14.5 / 6.4 s); video run `v138v_sprint_freeze_scenario` (45 s, 35 fps) 0. Remaining events in these runs are not animation
freezes: GR core-contact reactions against real, visible obstacles (pine trunks, `SM_PineStone02` rocks, a fence post, the
house wall and steep landscape) - a 1.2 s root-motion contact montage (`BP_GR_Player` EventGraph, `GR_CORE_CONTACT`) during
which Motion Matching underneath ping-pongs in a vendor 180 pivot tail; and one start/bump/stop stutter loop against an
unwalkable slope ~100 m outside the refuge (runs of 180 s leave the refuge: there is no boundary; the west route also wades
waist-deep through the pond with no water response).

**ACCEPTANCE**: technical **PASS** (>= 3 x 180 s real-map runs with 0 freezes + 35 fps video). Visual acceptance: user.
Obstacle-contact handling (post-contact pivot ping-pong, slope stutter) is reported as a separate open item (section 12).

## 2. Standing mouse turn posture switch (priority 2)

**TRACE**. Per-frame ownership during a standing turn: `BP_GR_Player.GR_UpdateIdleTurn` (called from `GR_UpdateRig`) plays
the turn clip as a full-body `PlaySlotAnimationAsDynamicMontage` in DefaultSlot whenever the character stands (speed < 5,
no input, grounded, no montage) and |control - actor yaw| enters 42-67 / 67.5-112 / 112.5-157 / 157.5-181 deg. Its standing
branches used the **vendor** clips `/Game/AAMS/AAMS/Animations/Locomotion/Idle/M_Neutral_Stand_Turn_{045,090,135,180}_{L,R}`
(90 deg alternatively the LookStrafe sample `A_LS_M_Relaxed_Stand_Turn_090_*`). Every V1.3.7 standing-turn step played one
of these montages (16 / 16), so the screen showed the AAMS ready stance (bladed feet, toe-out, hip / shoulder twist) while
the SHM MM selection underneath was hidden.

**ACTUAL CHANGE** (`install_idleturn_shm.py`, `install_idleturn_settle.py`, `BP_GR_Player` compiled UP_TO_DATE):
- the 8 standing literals and both 90 deg Select options now use the project-stance `SHM_M_Neutral_Stand_Turn_*` clips
  (identical length, root-motion flags and root turn +-45 / 90 / 135 / 180 deg with 0 translation - same gameplay rotation);
- direct angle routing with a latched intent: the trigger additionally requires a settled look (no `IA_Look` pulse for
  0.15 s, `TW_LastLookTime`) OR |intent| >= 157.5 deg, so a slow sweep produces one turn of the final bucket and a slow
  180 sweep one 180 turn. Crouch branches untouched.

**AFTER** (`v138f_tip_flick` / `_slow`, real `IA_Look`, montage asset logged; `turn_audit.py`, rendered body, 0.1-2.4 s after
the step):
