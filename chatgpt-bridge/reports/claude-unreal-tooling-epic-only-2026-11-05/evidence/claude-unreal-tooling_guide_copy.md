## Done means
A change counts only with all that apply: the edit, a readback of the value, a compile when the asset needs one, a visual check of a real image, and a save through `gsave.sh` confirmed by the gate log and a reread. A tool that returned without an error proves none of these. Keep technical pass and visual acceptance separate.

## Write rule
Epic MCP does not apply the runner gates by itself: no lock, manifest, backup or PIE check happens on its side. MCP calls edit in memory under the held lock (`lock233.sh`), never during PIE.
Save with `bash Tools/ClaudeUnreal_20261105/gsave.sh <owner> <name> /Game/...`, which takes the verified backup and runs a manifest-limited write job.
`AssetTools.save_assets`, `SceneTools.save_actor`, `AssetTools.delete` and `move` bypass the gates: do not use them on project assets.
`ProgrammaticToolset.execute_tool_script` is untested here.

## PCG notes
- Local examples: `/PCG/SampleContent/SimpleForest/PCGGraphs/SimpleForestWorldRayHits` (works on any collision surface), `/PCG/GraphTemplates/TPL_Showcase_*`, `/PCG/SampleContent/HiGenForest`.
- Project graphs `PCG_C01_Forest`, `PCG_C01_GroundDetail` and `/Game/Calysto/*` read properties of Calysto actors; they do not run alone in a test level.
- Graph parameter: `SetGraphParams` (`description`, `containerType`, `defaultValueJson` are required), `AddNode` with the localized type `Grafik Parametresini Al`, output pin `Out`, connect to the node's parameter pin.
- Instance overrides use the camelCase schema name (`treeDensity`). `SpawnGraphInstance` returns `{actor, graph}`; pass `actor` as `pCGVolume`.
- `treeDensity` on the test graph: 0.01 gives 15 trees, 0.03 and 0.06 both give 25. Why it stops at 25 was not measured, so a raised value with no change proves nothing; test downward too.
- Check results by instance count, mesh name and ground trace (`Tools/ClaudeUnreal_20261105/pcg_check.py`), not by an empty error list.

## Known bad or limited calls
| Call | Result |
|---|---|
| Nwiro `create_widget_blueprint` | Crashed the editor in `InitializeWidgetBlueprintRoot` (SF52 pass); no changelog fix. Do not call it; duplicate an existing WBP |
| `BlueprintTools.read_graph_dsl` | Returned an empty string for `BP_GR_MaskBench` EventGraph with no error; an empty result is not an empty graph. Use `find_nodes`, `get_connected_subgraph`, `get_node_infos` (these worked) |
| `CaptureViewport` | `captureTransform` and `annotations` are required in practice although the schema marks them optional. The result is about 3 MB of base64: Claude Code writes it to a tool-results file; decode the file to PNG |
| `describe_toolset` on `BlueprintTools`, `UMGToolSet` | 60-74 thousand characters, over the output limit: Claude Code saves it to a file; read the names from there |
| `CaptureAssetImage` | Not supported for widget Blueprints |
| `ObjectTools.set_properties` on an array | Refuses size and element change in one call: change, grow with copies, change again (`pcg3.py`) |
| UE Python `WidgetBlueprintLibrary` | Not exposed here. `new_object(cls, outer=PC)`, `set_owning_player`, `add_to_viewport` works; find runtime widgets with `ObjectIterator` (the tree is `WidgetTree_0`) |
| Object arguments | Pass `{"refPath": "/Game/Path/Asset.Asset"}`, never a bare package path |
| Localized editor | PCG node type names are Turkish (`ListNativeNodes` with `bCommonOnly:false`) |
| `claude -p` from `claude.exe` | Says Not logged in on this machine; that is that shell only, the desktop app sessions are signed in |
